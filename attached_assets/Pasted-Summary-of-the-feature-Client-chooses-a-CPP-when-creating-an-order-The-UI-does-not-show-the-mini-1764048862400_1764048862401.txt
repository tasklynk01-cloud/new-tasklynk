Summary of the feature
•	Client chooses a CPP when creating an order. The UI does not show the minimum until the client types a value; after typing the UI shows validation if it’s less than allowed minimum.
•	The server enforces a minimum CPP (configurable) and will reject orders with CPP lower than the minimum.
•	After admin/manager accepts the job, they may request an additional amount (e.g., complexity fee). That becomes a pending addition that the client must approve and pay.
•	Client may optionally top-up or add a bonus after admin acceptance (top-up appears as optional UI element after acceptance).
•	Total order amount = (CPP × pages/slides) + requested_additional + client_bonus + other_fees (e.g., platform fee if any).
•	Only when payment status is confirmed does balances/invoices get updated and manager/freelancer payouts computed.
•	All changes propagate into invoices and are included in reports and balances.

Add server-side enforcement on order creation/update endpoints. Never trust client-side validation.

Create order (pseudo-code - Express/Node)
// POST /api/orders
async function createOrder(req, res) {
  const {
    client_id,
    title,
    pages_count = 1,
    service_type, // 'writing_page' | 'slide' | 'technical_page' etc
    client_cpp // optional if client sets
  } = req.body;

  // Determine minimum
  const minMap = {
    'writing_page': Number(process.env.MIN_CPP_WRITING || 240),
    'slide': Number(process.env.MIN_CPP_SLIDE || 150),
    'technical_page': Number(process.env.MIN_CPP_TECHNICAL || 270),
  };
  const min_cpp = minMap[service_type] ?? Number(process.env.MIN_CPP_WRITING);

  // If client supplied CPP, ensure it's numeric
  const cpp = client_cpp !== undefined ? Number(client_cpp) : null;

  // If client provided cpp but less than min -> reject
  if (cpp !== null && cpp < min_cpp) {
    return res.status(400).json({ error: `CPP is less than minimum of ${min_cpp}` });
  }

  // If cpp is null, set some default (platform chooses or prompts client later)
  const resolved_cpp = cpp ?? Number(process.env.DEFAULT_WRITER_CPP || 200);

  // compute base total and optionally double for single-spaced (client selects later)
  let total = resolved_cpp * pages_count;

  // persist
  const newOrder = await db.query(
    `INSERT INTO orders (client_id, title, pages_count, client_cpp, status_total_amount, last_amount_update_at)
     VALUES ($1,$2,$3,$4,$5,now()) RETURNING *`,
    [client_id, title, pages_count, resolved_cpp, total]
  );

  res.json({ order: newOrder.rows[0] });
}
Admin/Manager requests additional amount
•	Endpoint: POST /api/orders/:id/request-additional
•	Body: { amount: number, note: string }
•	Behavior: create a record in order_amount_adjustments with change_type='manager_request', set status 'pending' → notify client.
•	Client must approve: POST /api/orders/:id/approve-adjustment → updates adjustment status to approved, updates orders.manager_additional and recomputes status_total_amount.
Client adds top-up / bonus
•	Endpoint: POST /api/orders/:id/topup with { amount, note }
•	Create order_amount_adjustments with change_type='client_topup', status 'approved' (since client initiated) and immediately add to orders.client_bonus and recompute totals.
Recompute total function (atomic)
Always run one transaction when applying updates:
BEGIN;
UPDATE orders SET
  manager_additional = COALESCE(manager_additional,0) + $1,
  client_bonus = COALESCE(client_bonus,0) + $2,
  status_total_amount = (client_cpp * pages_count) + manager_additional + client_bonus
WHERE id = $3;
INSERT INTO order_amount_adjustments (...)
COMMIT;
Payment confirmation & balances
•	When payment_status becomes paid:
o	Create payments record with provider details (Mpesa).
o	Update invoices and balances:
	Freelancer balance increase = amount due to freelancer (compute after company cut).
	Manager balance increase = fixed assigned fees + submit fees per policy.
o	Use a DB transaction to update payments, invoices, balances together to avoid race conditions.

3) Frontend UI behavior & validation
Key UX rules:
•	On the order creation form, show CPP input but do not display minimum until user starts typing.
•	If typed value < minimum (fetched from server via GET /api/pricing/minimums?service=...) show inline validation and disable submit.
•	After order is accepted by admin/manager, show admin-requested additions and optional "Add Bonus/Top-up" button for client.
React validation snippet (simplified)
function OrderForm({ serviceType }) {
  const [cpp, setCpp] = useState('');
  const [min, setMin] = useState(null);
  const [touched, setTouched] = useState(false);

  useEffect(() => {
    // fetch min from server once (or fetch on blur)
    fetch(`/api/pricing/minimums?service=${serviceType}`).then(r=>r.json()).then(d=>setMin(d.min_cpp));
  }, [serviceType]);

  const showMinValidation = touched && min !== null;

  const isValid = !showMinValidation || (Number(cpp) >= Number(min));

  return (
    <form onSubmit={...}>
      <label>CPP (KSh)</label>
      <input
        value={cpp}
        onChange={(e) => { setCpp(e.target.value); setTouched(true); }}
        type="number" step="0.01" min="0"
      />
      { showMinValidation && Number(cpp) < Number(min) && (
        <div className="text-red-600">CPP must be at least KSh {min}</div>
      ) }
      <button disabled={!isValid}>Place Order</button>
    </form>
  );
}

4) Invoices & balances recalculation
Rules:
•	order_total = (client_cpp × pages_count * (single_spaced ? 2 : 1)) + manager_additional + client_bonus
•	When payment confirmed:
o	freelancer_amount = order_total × freelancer_share OR per your updated rule (you removed 70% spec earlier — use company policy).
o	manager_amount = manager_assign_fee + manager_submit_base + manager_submit_per_extra_page × (pages_count - 1) (per your example).
o	company_revenue = order_total - freelancer_amount - manager_amount - taxes/fees.
•	All computations should be performed in a transaction and a single place (service layer) to avoid duplication. Store computed snapshots to invoices table for accounting.
Add or update invoices table to include breakdowns:
ALTER TABLE invoices ADD COLUMN freelancer_amount numeric(12,2) DEFAULT 0;
ALTER TABLE invoices ADD COLUMN manager_amount numeric(12,2) DEFAULT 0;
ALTER TABLE invoices ADD COLUMN company_fee numeric(12,2) DEFAULT 0;
